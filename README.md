# task26092804

数字菜单屏的看板物化缓存库（Go，纯内存，无持久化）。

## 设计

- `Store` 持有全部状态：菜品表、看板定义、菜品→屏幕反向索引、每屏缓存。
- `DefineBoard` / `ApplyBatch` 共用一条严格递增的版本序列，由 `writeMu` 串行化；
  写操作只触碰变更条目与受影响屏幕（定义被替换的屏，或引用的菜品字段真实变化的屏），
  开销与变更条数、受影响屏幕数成正比。
- 每屏一个 `displayState`：`dirty`（最近一次影响本屏的版本）+ 原子缓存指针 +
  每屏互斥锁（singleflight，同屏同版本并发未命中只渲染一次）。
- 命中缓存的 `GetBoard` 只做原子读（`sync.Map` 只读快路径 + `atomic`），
  不取任何共享锁，不等待写操作或渲染。
- 未命中时在 `dataMu` 读锁下对定义与被引用菜品做一致性快照，释放锁后才调用 hook，
  因此被 hook 卡住的渲染只阻塞同屏的其他未命中，不影响写操作与其他屏。
- 缓存内容按 `dataVersion >= dirty` 判定有效；未受影响的屏直接复用缓存内容，
  返回版本号提升为调用时的全局版本（该屏数据未变，内容与新版本逐字段相同），
  从而同时满足一致性、新鲜性与单调性。
- 不保留任何历史版本，内存占用不随累计写次数增长。

## API

```go
st := menuboard.New(hook)              // hook 可为 nil
v, err := st.DefineBoard(id, def)      // 最多 6 分区，每区最多 40 个菜品 ID
v, err := st.ApplyBatch(changes)       // 最多 200 条 upsert/delete，原子生效
b, v, err := st.GetBoard(id)           // 返回看板与版本号
```

## 测试

```sh
go test -race ./...
```

覆盖：hook 阻塞期间写操作与他屏读取照常完成且不放回半新半旧看板、
多 goroutine 混合操作对照独立参考实现逐版本校验一致性/新鲜/单调、
渲染次数（无关批次不重渲染、并发未命中只渲染一次）、
批量校验与整批拒绝、upsert/delete 语义，以及 10 万菜品 × 5000 屏的规模冒烟。
